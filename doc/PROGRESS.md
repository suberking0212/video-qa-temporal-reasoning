## 维护规则

1. 下方“当前状态”可随进展更新；“进度日志”按时间顺序追加新记录，不回写或删除历史记录。发现历史记录错误时，追加更正记录并引用原日期。
2. 只记录已经发生、可以验证的事实。计划要写成“下一步”，不能写成“已完成”。
3. 每条完成记录必须给出可核验依据，例如测试命令及结果、评测报告、界面行为或可复现操作；仅写“已实现”不算验证。
4. 使用明确日期 `YYYY-MM-DD`。阶段状态统一为：未开始、进行中、阻塞、完成。
5. 阻塞项应说明具体原因、影响的需求 ID、已尝试的解决方式，以及需要谁/什么条件才能继续。问题消除后追加解除记录。
6. 技术实现问题和已知质量缺陷登记到 `TECH_DEBT.md`，进度记录只引用对应 `TD-xxx`，避免两个地方维护同一问题的状态。

- 最近一次验证结果：
- 当前阻塞（无则写“无”）：
- 下一步：

## 进度日志格式

每次有可验证的里程碑、阶段变化、重要阻塞或阻塞解除时追加一条：

### YYYY-MM-DD — 简短里程碑标题

- **关联需求：** PRD ID 列表；无直接关联时写“基础设施/项目准备”。
- **状态：** 完成 / 进行中 / 阻塞 / 解除阻塞。
- **本次进展：** 已经做成或发现的事实。
- **验证证据：** 测试、命令/结果、评测数据、可复现操作或产物位置；尚未验证则明确写“未验证”及原因。
